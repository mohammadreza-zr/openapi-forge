# Changelog

## 0.3.2

- **The config says what it must carry.** With `@mrzr/api-client` a request function whose route has path values, or whose query has a required parameter, no longer takes an optional config: `getFine(config: RequestConfig<Fine> & { addTemplateToUrl: { id: string } })`, and `params: <Operation>Query` joins the type when the query is required. axios does the same for a required query (`config: AxiosRequestConfig & { params: ListVisitsQuery }`). The config still goes to the client as it is; only its type is narrower, so `getFine()` with no id no longer compiles instead of asking for `/fines/{id}`. A body that may be left out is then typed `body: T | undefined`, since a required parameter cannot follow an optional one. `fetch` and Angular already took these as typed arguments.
- **`@mrzr/api-client`: a multipart body may be a plain object.** The body is typed `UploadPhotoBody | FormData` and the call passes api-client's own `isFormData: true`, which turns a plain object into the form (a file or list per entry, an object as a JSON field) and sends a `FormData` as it is, so `uploadPhoto({ file }, { addTemplateToUrl: { pet_id } })` works without building the `FormData`. The document says the body is multipart; the client does the rest. fetch, axios and Angular still take a `FormData`.
- Tests pin two things that were already true: a failed call is an error of the hook (`@mrzr/api-client` 3 rejects by default, `throwError: true`, so no option is written and `client.ts` stays `createClient()`), and a header declared on every operation is no warning with api-client or axios.

## 0.3.1

Two things 0.3.0 dropped, put back: they are what an app that invalidates by group and passes a route param straight in relies on.

- **`lists()` and `details()` are back** in every `<tag>Keys`: `lists: () => [...petsKeys.all, "list"]` and `details: () => [...petsKeys.all, "detail"]`. A read with a path id is a detail, any other a list; its key is the half, the operation's route and the arguments — `[...petsKeys.details(), petsEndpoints.getPet, petId]`, an infinite list `[...petsKeys.lists(), petsEndpoints.listPets, "infinite", params]` — so one call invalidates every list or every detail of a tag.
- **A query hook waits for its path ids.** `useGetPetQuery(petId: string | undefined)` is not enabled until the id is there (`{ enabled: petId !== undefined, ...options }`; in the reactive libraries the same as a getter), and no request goes to `/pets/undefined`. The options you pass come last, so `enabled` can still be forced. The key reads a missing id as `""`, `0` or `false`. Mutations are unchanged: their ids are variables.

## 0.3.0

**Breaking — every built-in client is called as itself.** The package generates code; it no longer decides how a client behaves. Each generated function calls the client you chose, with that client's own config, and returns what that client returns. The four clients no longer share a runtime: they are four different worlds, and the generated code differs between them.

- **`@mrzr/api-client`** — `apiClient.get(…)` / `.post(…)` with api-client's own `RequestConfig`; a call returns its `IRes<T>`, so a hook's `data` is the `IRes` (`data.data` is the payload). `client.ts` is one line, `export const apiClient = createClient();`; it finds its base URL in the environment itself. An operation of a backend service is `apiClient.service("files").get(…)` through api-client's `services` plugin — **only when the layer has several services**; one service is the client's own base URL and no plugin is written. `client.ts` is written with `services(API_SERVICE_BASE_URLS)` for several, and no `baseUrl` is put in the call. (Add the plugin to an existing `client.ts` by hand.)
- **axios** — `http.get<T>(url, config)` on the instance `client.ts` exports (`export const http = axios.create({ baseURL: import.meta.env.VITE_API_URL })`), with an `AxiosRequestConfig`; a call returns an `AxiosResponse<T>` and a failed status is an `AxiosError`. Nothing of the instance is overridden: a query list is written the way axios (or the `paramsSerializer` you set on the instance) writes it, and the run lists each one so you can check it against the document.
- **fetch** — the platform's `fetch(url, init)` with a `RequestInit`; a call returns the `Response`, a failed status resolves as it does in `fetch`, and reading the body is yours. Every call starts from the `baseUrl` of `client.ts`; the query string is built in the function from the document's parameters, a JSON body is `JSON.stringify`-ed with its `Content-Type` (a `Content-Type` you pass in `init` wins). `ApiResponseError` is gone. **`fetch` has functions only**: `http: "fetch"` with `target: "hooks"` is an error (use `--target requests`), because a query hook over a raw `Response` would cache a stream and never see an error.
- **Angular** — an `@Injectable({ providedIn: "root" })` service per tag over the injected `HttpClient` (`inject(PetsService)`); a method returns `HttpClient`'s `Observable<T>` and a failed status is an `HttpErrorResponse`. No `configureClient`; every call starts from the `baseUrl` of `client.ts`, and `HttpClient`'s interceptors still apply. Hooks are Angular Query's, so `http: "angular"` with another `library` is an error (use `target: "requests"` for the service alone). `HttpClient` takes no `AbortSignal`: unsubscribe from the `Observable`. A form body is typed `HttpParams`; a query parameter `HttpClient` cannot write (an object, a file) is left out and listed.
- **Gone from the runtime:** `configureClient`, `GeneratedRequestConfig` and the shared `request` wrapper with its path, query, header and body helpers. `types.ts` keeps `ApiEnvelope` and `ApiListData` and the library's option types. A custom transport (`client: "custom"`) is unchanged and brings its own config type.
- **No envelope unwrapping at run time.** `isEnvelope` is gone from the built-in clients and `result: false` is no longer an error. With `@mrzr/api-client`, which takes the `data` of a `{ data }` answer itself, the types still speak of `data`; with the other clients the answer is typed whole (`runtime.envelope` can still describe a custom transport).
- **Bodies are the client's.** A multipart body is typed `FormData` and a urlencoded one `URLSearchParams` (`HttpParams` for Angular) — the bodies the clients send as they are; the generated code names a `Content-Type` only for a text or binary body, which the client would label otherwise.
- **Header parameters.** With `@mrzr/api-client` a header parameter is no longer an argument (headers are the client's own: `createClient({ headers })`, or `headers` in the config of a call). With axios, `fetch` and Angular it stays an argument of the function, the hook and the query key.
- **The query is `params`**, the name all four clients give it (a custom transport's `requestKeys.query`). With api-client and axios a request function has no query argument: the query is `params` in the config of the call, so `listCities(config)` is `apiClient.service("files").get(url, config)` and the config goes to the client untouched; the hooks keep it typed and pass `{ params, signal }`. With api-client the path values are `addTemplateToUrl` in that config too (`getCityByID(config)`; the hook passes `{ addTemplateToUrl: { id }, signal }`), so a request function takes only its body and the config. `fetch` and the Angular service take the path values and `params` as arguments, since neither has a config to carry them.
- **The document decides the request**: the route (filled in), the query, the declared headers, the body's shape, and a non-JSON answer (`text/*`, or anything else as a `Blob`) is asked for with `responseType` where the client has one.
- An `infinite: true` read whose answer is not `{ count, list }` (an envelope with a client that does not unwrap it) gets no infinite hook, and the run now says so. A page is read from `response.data` (api-client, axios) or `response.json()` (`fetch`), because paging has to.
- **A detail query takes its id as it is.** `useGetPetQuery(petId: string)` no longer accepts `undefined`, waits for it, or guards with `enabled`; pass `enabled` in the hook options to hold a query back.
- **Query keys are short and read the route.** A key is the tag, the operation's route — read from the tag's `<tag>Endpoints` map, so it is written once — and the arguments its answer depends on: `[...petsKeys.all, petsEndpoints.getPet, petId]`, instead of the tag, a `list` / `detail` layer, the route and the arguments. `lists()` / `details()` are gone (invalidate `<tag>Keys.all`, or a prefix such as `[...petsKeys.all, petsEndpoints.listPets]`). The request functions read their URL from the same map, so a path moves in one line.
- **Every client reads the API's base URL from the environment.** api-client finds its own (it reads `VITE_API_URL`, among others); axios takes `import.meta.env.VITE_API_URL` (the name is `baseUrlEnv`, `--base-url-env`) as its instance's `baseURL`, and `fetch` and Angular start every call from the `baseUrl` their `client.ts` exports from it; the routes are written without `apiPrefix`, which that URL carries.
- **A service's base URL is read from the environment by default**, in `<baseUrlEnv>_<SERVICE>` (`VITE_API_URL_FILE_STORE`); the generated code imports nothing from your project unless you name `runtime.services.fn`. api-client refuses a service with no address and says so. `runtime.services.baseUrls` gives literal URLs.
- **No invented names.** A part of an `allOf`, an option of a `oneOf` or `anyOf` and a tuple member that is an inline object is written where it stands; before, it was hoisted into a type named by position (`GetUserResponsePart1`, `…Option0`), and identical ones became aliases of each other.
- **Which identical models become one is decided by identity, not by name.** A schema the document names is a contract of its own and never becomes an alias of another (a request body is not the entity it resembles). An inline object the generator named joins an identical one only when its shape says something of its own — it names another model, or has three fields; a bare `{ id, name }` or `{ file }` stays what it is. Before, two models merged when one name contained the other.

## 0.2.2

- **Valid code for awkward names.** An `operationId` or path parameter that is a reserved word (`delete`, `default`, `in`, `for`, …) or starts with a digit (`2fa`) used to be written as it was, which does not compile; it now takes the same fallback name an empty one does. A schema that starts with a digit (`2FA`) becomes `_2FA`, and its Zod validator `_2FASchema`.
- **Swagger 2.0 query lists.** `collectionFormat` is now carried over (`csv` is the default there, `ssv`, `pipes` and `multi` too), so a list the client would send as repeated keys instead of one line is reported, not changed in silence.
- **`pull` compares Swagger 2.0 documents correctly.** The documents are converted before they are compared, as `diff` always did; before, a changed response or definition of a Swagger 2.0 service showed no change at all. A service that moves between JSON and YAML no longer leaves its old document in `specsDir`.
- **`diff` names a parameter with a colon whole** (`filter:status`), not the part before the colon.
- **A tag the document drops no longer leaves its module behind.** The run removes generated files it no longer writes (only those that still carry the generated banner) and `--check` reports them as stale; before, the old module stayed, referred to models that were gone and `--check` said the output was up to date.
- **`--ca` adds to the public CAs** instead of replacing them, so a run that reads a private host and a public one verifies both; the headers of a document request are not sent on to another origin when `--ca` / `--insecure` reads it and the server redirects.
- `runtime.requestKeys.body: false` is accepted with `http: "api-client"` (it only threw for a real key); `--interval` must be a positive number; `--watch` no longer says it watches the config (it never did); `doctor`'s duplicate-`operationId` hint names the method suffix.

## 0.2.1

- A repeated `operationId` is named with the method appended (`getUserGet`), as the README says; before, the first repeat was already numbered (`getUserGet2`). A number is added only when the name with the method is taken too.
- Releases are cut from a `v*` tag (`npm version patch && git push --follow-tags`): the tag must match `package.json`, three Node versions verify, then npm trusted publishing and a GitHub Release.

## 0.2.0

- **The default `http` is `"api-client"`** (it was going to be `fetch`): a project that does not name one now gets a client over [`@mrzr/api-client`](https://www.npmjs.com/package/@mrzr/api-client) and needs that package. `http: "fetch"` is still there and needs nothing; the three runtime files are written once, so a layer already generated keeps its `client.ts`. A `DELETE` operation with a body is left out under the default (see below), where `fetch` sends it.
- `http: "api-client"` (`--http api-client`): the built-in runtime sends with [`@mrzr/api-client`](https://www.npmjs.com/package/@mrzr/api-client), so its token refresh, tab sync and plugins apply — `configureClient({ instance: createClient({ … }) })`, the way axios and Angular take theirs. Bodies and answers are handled by the same code as in the other clients. Its `delete` takes no body, so a `DELETE` operation with one is left out and reported. This replaces the adapter the 0.1.0 README showed for a custom transport.
- `doctor` looks for `@mrzr/api-client` when it is the chosen client; the conformance matrix is 9 clients × 62 documents, and every hook library is run over it.

## 0.1.0

First release.

- Generates models, request functions, route and query-key factories and hooks from OpenAPI 3.0 / 3.1 and Swagger 2.0 documents (JSON or YAML; a file, a folder of files or a URL).
- Clients: `library` picks the hooks — `react-query` (default), `vue-query`, `svelte-query`, `solid-query`, `angular-query`, `swr` — and `http` picks what the built-in runtime sends with — `fetch` (default), `axios` or Angular's `HttpClient` (`angular`, interceptors apply). The reactive libraries read each hook argument where the request is made, so a ref, a signal or a getter keeps the query in step. `client: "custom"` imports your own transport instead.
- Several services in one layer: documents are merged, conflicts are decided once and committed.
- `openapi-forge pull`, `--check` (fails CI when the committed layer is stale), `--watch`, `doctor`, `init`.
- `openapi-forge diff` and a change report on `pull`: breaking / risky / safe, by hook name.
- `zod: true` writes `schemas.ts`; `infinite: true` adds infinite-list hooks.
- Same-shaped query and variable types are written once (aliases, or `Omit<…> & {…}` when close).
- An incomplete document never produces broken output: unknown spots are typed `unknown` and listed with the operation and the part. What the client cannot do as the document asks (a cookie parameter, a query written on one line) is listed the same way, not sent differently in silence.
- The types are true of what is sent and received: only an operation whose response schema is an envelope is unwrapped (`isEnvelope`), `ApiListData` needs `count` and `list` to be `required`, header parameters are arguments (also of infinite-list hooks), a `DELETE` sends its body, `runtime.list.assumeRequired` takes `count` and `list` as always there, bodies go out as their media type (multipart with lists and objects, urlencoded, text, bytes), an answer is read by its `Content-Type` (JSON, text or `Blob`), and an object in a query is `a[b]=1`.
- `@mrzr/api-client` works as a custom transport: the README has the adapter, and `npm test` compiles and runs it against the real package. A header that is not text (a number, a flag) is written with `String()` in the generated code, so a transport that types its headers `Record<string, string>` takes it as it is.
- Written in strict TypeScript; the package ships `dist/` with `.d.ts` files.
- `npm run conformance` is a client × document matrix (8 × 61: 60 public documents of `@readme/oas-examples` plus the client-test fixture), generated and type-checked with `tsc --strict`. `npm test` runs the three HTTP clients and all six hook libraries — each over `fetch` and axios, Angular Query also over Angular's `HttpClient` — against a local server (data, reactive arguments, header arguments, a missing id, mutations, infinite lists, abort on teardown).
- Checked against two live backends (NestJS and FastAPI).
